Fix encounter_rule/conduct_rule priming bias + scenario-PG pass_criteria/warnings bug

- pipeline/oow_agent_spec.py, Basic Simulator/app/agents.py: reworded the
  encounter_rule/conduct_rule JSON schema fields in SYSTEM_OOW_AGENT and
  BARE_SYSTEM from a flat ordered "Rule 13, Rule 14, Rule 15, or 'none'" list
  to a bare 'Rule <N>' template with no rule numbers or situation mappings in
  the prompt -- measured a ~80%-cited/33%-precision bias toward citing "Rule
  13" regardless of the true encounter geometry, and the model must derive
  the rule from its own COLREG knowledge, not a prompt cheat-sheet.
- pipeline/track2/build_oow_scenarios.py: to_trace_record()'s "warnings" field
  was derived via a naive "not"/"avoid" substring filter over pass_criteria,
  which misclassified several REQUIRED actions (e.g. "alters course to
  starboard (not port)") as pitfalls -- rendered under PG guidance's "Avoid:"
  line, telling the model to avoid the correct action. Now always [] (matches
  build_oow_scenarios_leo.py's own convention).
- Data/OOW/OOW_Agents_Training/{oow_scenario_reasoning_traces.jsonl,
  oow_pg_scenario.json, oow_pg.json}: patched/rebuilt locally to reflect the
  warnings fix (240/390 scenario traces had a contaminated warnings list).
- Other in-progress/generated files from concurrent work in this session
  (additional_* sweep run logs/audit output, UM rescaled missions, outcome
  DPO/reflection builders) included as-is per repo convention that all
  generated data is tracked.
